# Commit message convention

BEYOND uses a Conventional Commits-inspired format:

`type: concise description`

## Common types

- `feat`: add a capability or experience.
- `fix`: correct a defect.
- `docs`: documentation-only changes.
- `style`: formatting changes without behavior changes.
- `refactor`: restructure code without intended behavior changes.
- `test`: add or update tests.
- `build`: build system or dependency changes.
- `ci`: continuous integration changes.
- `chore`: maintenance tasks.

## Examples

- `feat: add immersive gallery`
- `fix: correct mobile navigation`
- `docs: explain release process`
- `chore: add GitHub templates`

Keep the subject concise and accurate. These are project conventions, not Git requirements.
