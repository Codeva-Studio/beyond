# Project management

## Issues

Use Issues to track actionable bugs, features, tasks, and documentation work.
Apply labels consistently so work can be filtered and prioritized.

## Milestones

Use a Milestone when a group of Issues and Pull Requests shares a meaningful delivery goal.
A Milestone is optional; do not create one without a concrete target.

Use `docs/templates/MILESTONE_TEMPLATE.md` as a starting point for the Milestone description. Copy its contents into GitHub when creating or editing a Milestone; GitHub does not load this file as an automatic Milestone template.

## GitHub Projects

Use a Project board when a visual workflow, custom fields, or cross-repository planning
provides real value. A small solo project may be adequately managed with Issues and labels.

## Iterations / sprints

Iterations are optional time-boxed planning periods. Use them only when BEYOND is actively
planning work in recurring cycles.

## Configuration location

Labels, Milestones, Projects, iteration settings, and branch protection are configured
in GitHub's interface or through explicit automation. Documentation files alone do not create them.
